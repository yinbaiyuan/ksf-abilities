# 高级交互设计师 · 使用说明

帮助你把网站、后台、工具或移动端设计到可查看、可操作和可验证。既能从新产品开始，也能只处理一段流程、一处界面或一次评审。


## 怎么开始

在 KSF 中直接说“请高级交互设计师帮我……”，再提供现有页面、截图、工程、需求或参考中的可用部分。未明确指定时，当前能力路由也可以按任务适用性选择本搭档；名称相近不保证每次都会被自动选择。

示例请求：

- **新产品：**“请高级交互设计师为设备运维工作台设计核心体验。用户主要处理告警、查设备和追踪处理记录，先帮我理顺流程，再给几个可见的视觉方向。”
- **已有界面优化：**“请高级交互设计师优化这个订单页。沿用现有品牌，重点解决筛选难用、列表难扫读和移动端溢出，做到可运行。”
- **表单与交互：**“请高级交互设计师检查这段移动端申请流程，减少重复输入，补齐校验、返回修改、中断恢复和提交结果。”
- **设计评审：**“请高级交互设计师评审这几个页面，按对用户任务的影响排序，给出证据、改法和验证办法。这次先不修改。”
- **原型与交接：**“请高级交互设计师把这个已定方案做成可操作原型，使用模拟数据，说明状态、适配和开发验收标准。”

已有明确范围、风格、技术栈或交付形式时直接说明；不必先填写整张问卷。

## 会怎样工作

先看已有事实与界面，给出明确判断，再补影响结果的重要缺口。按任务选择需要的工作：体验架构、视觉方向、完整界面、原型/实现或评审。

新产品尚无风格时，用同一代表页面和内容制作2–3个可见小概念，附推荐与取舍；已有明确方向或仅局部优化时直接沿用。方向需要你选择时展示具体成果，已授权自主决定时按推荐推进。

设计会覆盖相关状态、微文案、响应式和无障碍。原型或实现会核对关键操作，明确模拟数据与真实连接边界。评审按位置、证据、影响、改法和验证组织。

实际交付依本次要求，可包括界面/原型入口、关键流程与状态、变量和组件规则、开发说明、问题清单及验证结果。小任务只保留必要内容。

## 可裁剪模板与边界

- [设计简报](templates/design-brief.md)：保留本次任务需要的部分，优先由搭档依据材料填写。
- [评审与验证记录](templates/review.md)：区分观察、判断、假设、已修和未验证。

产品的品牌、设计变量、设计文件、代码和研究记录留在实际项目/工程。通用能力本身不保存跨任务产品状态，也不自动学习或保存临时审美偏好。

工具依当前环境选择；Figma不是前置条件，未连接时可按任务使用代码原型或交接规格。无法运行、未制作画面、未进行真人测试等限制会分别说明。生产操作、发布和公开分享服从具体任务授权。

## 可选支持与实测成果


本轮接入视觉方向、定向检索、规范记录和局部打磨四项支持。搭档本身不绑定第三方工具，两个原全局入口移除后由基本功按需读取；designmd CLI保留。具体清理与验证结果见对比目录中的installation-check.json与structure-check.json。

## 液态玻璃专项

用户明确要求Web玻璃折射或苹果式玻璃控件时，采用[液态玻璃设计与实现](../../基本功/competency.yinbaiyuan.liquid-glass/competency.md)。该基本功随附固定提交的原始Skill、引擎、组件、路径与参数说明，不要求所有UI任务全量加载。

示例：“请用液态玻璃基本功重做导航和按钮，背景采用登山高峰意象，保留现有PC交互。”先建立原始组件基准，随后完成已授权实现、状态和回退核对；验收以实际画面和行为为准。
