# 系统架构师试用指南

在当前 KSF 对话中直接说“请系统架构师……”即可请求使用。它通过已有能力路由被发现，由当前 Agent 读取定义后履责，不需要另开 Agent、安装外部框架或修改根入口。

## 可以直接使用的说法

- “请系统架构师评审 `<实际工程绝对路径>` 的 `<具体链路>`，用代码证据说明问题，给最小改造建议，先不要改代码。”
- “请系统架构师设计一个 `<用途>`。已知约束是 `<运行环境、数据、兼容等>`，先给最简单可用结构及取舍。”
- “请系统架构师根据这份需求和现有设计形成实施交接，写清接口、失败处理、验证和迁移步骤。”
- “请系统架构师解释项目为什么采用 `<某选择>`；找不到历史依据就说明未知。”

可提供已有工程路径、最重要流程、现行设计/ADR 和本次要改善的问题。其余可从工程取得的事实由搭档读取；不需要先填写完整问卷。调用基本功和取证不会自行改变代码，明确要求实现时才进入相应执行范围。

## 能力组成

| 基本功 | 何时使用 |
| --- | --- |
| 架构分析与约束澄清 | 恢复现状与证据，明确影响决定的约束 |
| 架构设计与模式选择 | 选择必要结构，定义边界与验证 |
| 架构评审与渐进改造 | 检查真实问题，组织可分步交付的改造 |
| 架构决策记录 | 记录重要取舍，解释历史依据，交接实施 |
