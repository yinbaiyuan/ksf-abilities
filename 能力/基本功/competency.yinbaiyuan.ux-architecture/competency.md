# 体验架构与交互设计

## 独立结果与输入

把用户要完成的任务、产品约束和现有体验，转成能指导界面设计与实现的设计简报、信息架构、关键流程和交互约定。适用于新产品、功能设计、流程改造和复杂表单；单纯视觉微调只补其直接依赖的交互信息。

必需明确：谁在何种情境完成什么任务、完成后的可观察结果、当前设计或新建范围。可选输入为访谈、行为数据、客服问题、现有界面、业务规则、内容和技术限制。先使用本次材料和项目入口指向的事实；研究资料按当前目标定向获取。

缺关键用户或任务信息时，先给具体候选和推荐，集中补问影响流程的部分。可用合理假设推进结构探索，但在简报中标明；权限、费用、不可逆动作、关键业务规则未知时，不把猜测写成已确定行为。资料不足不等于需要新建项目或扫描全部知识库。

## 方法：从任务到可检查的体验

### 1. 建立任务基线

用“用户—触发情境—目标—现有办法—障碍—完成标准”描述核心任务。将用户原话、观测结果、产品要求、外部模式和设计假设分开。已有产品沿实际界面或调用链验证入口、终点和限制，不凭页面名称推断工作方式。

新设计采用发现、定义、发展、交付的发散与收敛思想；小任务可一次完成必要判断，不强制研究轮数。访谈与测试需要真实参与者；AI推演只能提供假设、提纲和模拟情境。

选出本次最重要的完整任务，确定成功、耗时、错误、求助或返工中哪些值得观察。高频工具优先减少重复输入、切换和恢复成本；重要决策保留理解后果与核对的空间，不能只用点击次数衡量效率。

### 2. 组织信息与导航

梳理内容、对象、关系、角色和权限，用用户熟悉的概念组织分组、命名和入口。区分全局导航、局部导航、上下文动作和搜索；确保当前位置、返回路径与主要下一步可被发现。

内容分类分歧大时，提出卡片分类或树测试方案并说明待验证；没有真实参与结果时不声称完成验证。对长列表和复杂对象，根据查找任务选择筛选、排序、搜索、保存视图或分组，避免一次展开全部选项。

### 3. 设计完整流程

画出从真实入口到成功结果的主路径，再补有实际意义的分支、取消、返回、中断恢复和跨设备衔接。明确每一步用户看到什么、可以做什么、系统怎样响应、下一步条件是什么。

高频流程按需要提供默认值、最近使用、批量操作、快捷键或渐进披露；默认值须有依据且可见、可改。引导式流程适合有依赖的步骤；任务可独立并允许任意顺序时才考虑任务清单。长流程检查保存进度、返回修改与提交前核对的需要。

破坏性操作根据后果选择撤销、确认或更强保护；不能把所有动作都加确认框。涉及权限限制时解释当前能力和下一步，不将其混同字段格式错误。

### 4. 定义页面与交互状态

为关键页面列出目标、信息优先级、主次动作、入口/出口和内容来源。为关键控件说明可发现性、触发方式、反馈、键盘/触摸行为、焦点去向及必要的关闭/返回方式。

按适用性补齐：初始、加载、空白、搜索无结果、部分成功、成功、错误、权限不足、禁用、离线、中断、未保存离开、重复提交。每个异常给出恢复动作、输入保留策略和结果核对办法；不适用项说明原因，无需凑齐状态数量。

表单只收集任务所需信息，标签表达数据含义，提示放在需要时。校验失败保留用户输入并给出具体修正路径；校验时机根据输入方式与用户证据确定，避免在用户尚未输入完成时持续打断。并发编辑或网络结果未知时说明当前状态并先核对，避免重复提交。

微文案使用用户语言，按钮用可理解的动作表达结果；错误说明发生了什么、是否保留工作和如何继续。将必要业务信息与实现内部术语分开。

### 5. 检查与交接

按主任务逐步走查：是否知道从哪里开始、当前发生什么、怎样完成和出错后如何恢复。对关键替代方案写明选择依据、代价和待验证条件；用户纠正任务或规则时只重审受影响流程。

交给视觉/原型环节：简报、结构/流程图或等价表、关键页面说明、适用状态、业务事实与假设、未决项及验收任务。仅评审时直接交付问题与修正建议，不扩成全量重设计。

## 质量与失败修正

| 要求 | 失败信号与修正 |
| --- | --- |
| 核心任务可从入口走到成功结果 | 只有页面清单：补入口、条件、反馈和结束证据 |
| 信息与操作符合使用者心智 | 按数据库表或组织架构直接分菜单：重新核对用户查找和操作任务 |
| 效率改善有具体机制 | 只声称“更高效”：指出减少何种重复、切换或返工，并设计验证 |
| 重要状态可被理解并恢复 | 只设计正常态：补实际相关异常、数据保留和恢复路径 |
| 事实与假设可区分 | 虚构访谈/用户画像：恢复来源性质并标明缺口 |

## 示例与边界

以下为模拟示例，非真实业务测试。

- 正例：运营人员批量调整商品库存。先确认选中范围、权限和并发规则，设计筛选→选择→修改→预览→提交→逐项结果→失败项重试，配合可发现的批量操作和输入保留；交付完整任务与恢复路径。
- 反例：为了“简洁”只留一个提交按钮，失败后清空输入且不说明哪些记录成功。修正应恢复结果可见性和可重试范围。
- 边界例：用户只要调整标题字号。保留现有流程，仅核对标题层级、可读性及换行，不启动完整用户研究。

## 资料采用与验证边界

下列一手资料于2026-10-25读取。按问题定向查阅，模式须结合产品与平台，不能原样移植全部规则；涉及变化中的平台能力时复核现行官方说明。不可获取时保留已知依据，标明受影响判断。

- [Design Council 双钻](https://www.designcouncil.org.uk/resources/the-double-diamond/)：用于问题界定、方案探索与小范围验证。
- [NN/g 十项可用性原则](https://www.nngroup.com/articles/ten-usability-heuristics/)：用于反馈、一致性、防错、识别、效率与错误恢复判断。
- [GOV.UK 任务清单](https://design-system.service.gov.uk/components/task-list/)：仅在多任务可独立完成、需要跨次处理等证据成立时采用。

首版具备方法定义；验证证据见搭档的验证记录。结构检查与情境走查不证明真实用户成功率或效率改善。当前业务底稿由项目/任务持有，无需跨任务私有状态。
