# 交互原型与界面落地

## 独立结果与输入

把设计目标、流程、界面和状态约定，转成适合当前验证问题的可操作原型，或按本次授权完成实际界面与开发交接。可以从粗线框开始，也可以承接已有设计；保真度由要验证的问题决定。

必须核实交付范围、目标设备、已有工程/设计文件、当前技术栈、关键交互、数据性质、运行和保存位置。读取实际工作区及其规则；没有工程时先明确本次只做原型还是需要实际工程，由当前工作区安排承接，不把通用能力目录当产品工程。

设计尚有关键分歧时可制作局部验证件，保持未定内容可替换；真实接口、权限、业务后果不明时使用标明的模拟数据或等待必要事实，不将演示连接成生产行为。

## 方法：验证问题决定原型与实现

### 1. 选择最小足够保真度

| 要验证的问题 | 默认产物 |
| --- | --- |
| 信息顺序、导航与流程是否合理 | 低/中保真可点击流程或线框，保留实际标签和任务 |
| 视觉方向、布局与内容层级 | 同一代表页面的高保真片段，可见且可比较 |
| 表单、表格、快捷键、响应式或动效 | 能实际操作的代码/工具原型，覆盖相关状态 |
| 产品界面交付 | 在已有技术栈中实现，并核对真实连接与交付范围 |

已有合适工程、组件和设计系统时直接复用。小原型选择当前环境最简单的可运行方案，不为演示引入无必要依赖；真正产品实现仍以工程维护、测试和部署约定为准。

### 2. 核实工具与执行条件

优先使用当前宿主实际可用的文件、代码、设计、浏览器和检查工具，遵循对应技能/插件和项目规则。使用Figma等工具前核实可访问文件、权限和实际编辑能力；未连接设计工具时可交付代码原型或规格，不声称已写入设计文件。

制作图片、图标或动效资产前核对用途、尺寸、格式及来源；使用生成式图像时遵循宿主工具约定。图片可表达视觉概念，但交互原型须有实际操作行为。

用户要求界面实现时推进已授权前端范围；需要新增后端、改业务规则或改变系统架构时指出依赖与取舍，并交回相应责任。发布、生产变更和对外分享按具体授权执行，原型完成不自动扩大权限。

### 3. 建立可操作行为

将页面/组件映射到流程、事件和状态，写清触发、前置条件、反馈、下一状态和失败恢复。相关按钮、导航、筛选、表单、弹层、返回/取消和提交结果实际可操作；未实现部分可见标注，不能把静态点击外观当完整交互。

模拟数据与真实数据、可演示行为与生产行为分别说明；样例不伪造用户、收入或运行结果。后端不可用时保留可验证的前端行为和状态入口；提交等待、部分失败、重试和结果未知等按设计范围实现。

涉及弹层与复合控件时落实语义、标签、键盘、焦点进入/退出与恢复；触摸和悬停行为分别考虑。实现已有设计变量和组件状态，按内容调整布局，不靠截断掩盖溢出。

### 4. 检查运行与视觉还原

先完成当前范围，再按目标设备进行一轮成组检查：运行/构建、关键路径、相关异常、键盘操作、代表性视口和实际截图。检查字体/资产是否加载、中文换行、布局、层级、颜色、组件状态与动效是否符合设计依据。

将发现的问题集中修正，再进行一次确认；只因新失败、未闭合风险或用户要求继续额外检查，避免无目标的反复微调。断网、接口受限或无法启动时，记录实际错误和已验证范围，继续静态核对及独立可做的工作，不把构建成功冒充视觉还原或用户效果。

对真实产品按工程规则运行与改动相称的测试；关键行为有风险时检查回归，纯展示性调整以实际视觉检查为主，不为每项样式写镜像测试。

### 5. 开发交接与交付

交接包含：实际成果入口、运行/查看办法、关键流程和状态、设计变量与组件映射、适配与输入方式、数据/接口边界、重要取舍、验证证据和未完成部分。依据已存在的唯一设计/工程文档维护，不复制另一份现行规范。

只要求设计交接时，提供开发者能执行的规格和验收任务，不自行扩成代码实现。只要求原型时，说明模拟边界与演示限制；已授权实现时继续完成当前范围并核验，而非停在“可交开发”。

## 质量与失败处理

- 成果能按说明打开并执行要验证的任务；关键控件失效时修复或明确范围，不以截图代替运行证据。
- 视觉、行为、内容与设计依据一致；确需偏离时解释原因和影响。
- 真实接口结果不明先核对，避免盲目重试引起重复副作用。
- 工具不可用仅阻止依赖它的部分；替代产物不得冒充原要求已经完成。
- 测试、截图和工具回执记录实际观察，当前Agent走查与真实用户测试分别表述。

## 示例与边界

以下为模拟示例。

- 正例：筛选工作台用明确标记的模拟记录实现搜索、筛选、详情、空结果和加载失败演示；在桌面/窄屏走完任务，交付运行入口和模拟接口说明。
- 反例：只摆出搜索框、按钮和数据卡片，点击全部无效，却称“完整原型”。修正需实现关键行为，或把交付名称收回为静态视觉稿。
- 边界例：用户只要求Figma开发说明。按可访问设计生成状态、尺寸规则和验收任务；没有授权时不新建前端工程。

## 资料采用与验证边界

研究依据于2026-10-25读取：[Apple 设计原则](https://developer.apple.com/design/human-interface-guidelines/design-principles)用于早期原型、真实环境检验和细节维护；[NN/g 可用性测试](https://www.nngroup.com/articles/usability-testing-101/)用于围绕真实任务选择原型与验证方式。

具体工具API、组件和平台能力以当前官方文档、实际工具契约和工程版本为准，使用前按需核实；依赖缺失时说明限制，不编造命令。首版未承诺特定工具接入或产品实现效果，验证记录由搭档持有。原型、截图、代码和任务进度留在实际工程/项目，无需跨任务能力私有状态。

## 可选专业支持

实现与验证不依赖固定 skill。已有界面需要局部布局、排版或收尾打磨时，可按[支持说明](supports/README.md)选择工具；先读包外适配，再读当前命令所需原始资料。完整新建流程本轮未验证，不默认触发 init、图片生成、额外Agent、安装或hooks。

按任务使用当前工程；视觉方向由已确认设计和视觉基本功提供。检索、规范和评审支持由其所属基本功按需读取，不在这里重复维护另一份包或设计主件。工具不可用时继续本方法能够独立完成的工作，并说明尚未执行的检测。
