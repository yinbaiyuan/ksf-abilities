# ADR 维护参考

## 适当粒度

一条记录解决一项可独立理解的架构取舍。相互约束的决定可在同一记录说明；独立决定分开并互链。简短记录保留背景、选择、代价和重评条件即可，不强制写长文。

## 状态与来源

- proposed：建议或待定，包括模型推荐；不能因代码生成或对象 active 自动接受。
- accepted：有明确采用依据；记录确认者/材料及时间，缺失时说明。
- rejected：本项提案已明确不采用，保留原因。
- deprecated：已不再适用且没有直接替代；说明退出影响。
- superseded：由新决定替代；保留双向链接。

保存提案不等于接受，接受不等于实现，实现不等于验证。回填历史决定时注明原始决定时间是否已知、本轮补记时间、依据和不确定性。

## 唯一落点

优先现有工程约定。没有约定时，使用实际工程 `docs/adr/0001-<主题>.md` 与 README 索引；此处是任务执行时的默认目标，不是要求每次加载基本功就创建目录。相同决定不在 KSF 项目、能力目录和工程各维护一份现行正文，跨位置用链接。

保存前核对最新编号和目标基线，避免并发覆盖。更新记录时核对相关索引及替代链接；不重编号历史文件。确认/保存已在用户授权内时连续完成，不增加每步审批门槛。
