# KSF 公用能力源

能力商店入口：[KSF 公用能力源](https://yinbaiyuan.github.io/ksf-abilities/index.json)。当前按两个搭档组合展示和交付，支持 Core 0.5.6 获取完整组合；组合成员管理及旧显式安装迁移使用支持该机制的新版 Core。

- **系统架构师 0.1.4**：包含4项0.1.2架构基本功，共5个独立能力对象。
- **高级交互设计师 0.1.4**：包含6项0.1.2设计基本功，共7个独立能力对象。

源内所有对象保留稳定ID和精确版本，搭档及其下挂基本功作为完整发布单元。当前没有数据包；今后挂载的数据包按同一规则随包交付。个人同ID能力仍优先，更新不覆盖个人原件。添加源不自动安装能力。

## 安装与更新

在能力商店选择搭档，预览完整成员后安装或更新。两个组合使用完整闭包的`ksf-ability-package-v1`包，兼容已发行Core 0.5.6；同字节`.ksfabi`文件可通过商店导入。

10项基本功退出独立商店展示，不单独生成新的发布包。为兼容0.5.6的精确依赖查询，目录保留隐藏的成员详情/版本入口，均指向所属搭档的完整包，供程序解析依赖；它们不是独立商品。新版Core按搭档整体管理，旧版已装的独立成员可保留，迁移和回退范围以安装预览为准。

原12个0.1.1归档逐字节保留，历史二进制和目录分片仍可寻址。新包包含完整必要资源，历史缺口不通过覆盖旧版本修补。安装副本可离线使用，源刷新和实际更新分开处理。

## 作者维护

源遵循`ksf-source.yaml` v2，`distribution.entries`只列两个搭档。快照仅为入口生成完整组合包，目录构建仅展示入口；各类型仍保持独立底层身份及复用能力。

```sh
npm ci --ignore-scripts
node scripts/snapshot.mjs --ksf-root <开发KSF根>
npm run build
npm test
npm run check
```

快照通过调用方KSF公共打包接口生成，需使用支持源发布入口及完整资源打包的开发Core。源自身须是独立Git根，位于KSF实例内时放在repositories直接子目录。重复生成同字节不变化，同版本异内容拒绝，`--initial`不能覆盖冻结版本。

Core基础能力随Core维护，不向本源重复发布；本源不作为Core离线副本。场景ID第二段必须为实际发布PR作者的GitHub用户名。可信发布检查读取base分支脚本，不执行head代码；实际运行及必需检查状态以仓库工作流、分支设置和CI结果为准。

私人试用记录、账号、个人设置、恢复备份和本机修订字段不进入发布内容。外部工具仅在许可明确时附带，保留许可与来源说明。迁移规则见[组合发布说明](迁移记录/2026-11-14-搭档整体发布.md)。
